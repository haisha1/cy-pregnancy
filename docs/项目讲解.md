## 一、项目角度讲解

### 1.1 项目是什么

「春雨孕算工具」（包名 `cy-pregnancy-app`）是一款面向**孕期超声场景**的工具型前端应用，核心提供三类确定性能力：



1. **日期与孕周计算**：末次月经（LMP）、已知预产期（EDD）、胚胎移植（IVF）、头臀长 CRL 定年、已知孕周等多种方式互查。

2. **胎儿生长测量与估重**：BPD（双顶径）、HC（头围）、AC（腹围）、FL（股骨长）、CRL 的录入，cm/mm 换算，Hadlock 四公式估算胎儿体重（EFW），并可绘制生长曲线、导出本地 PNG。

3. **超声专科工具与知识库**：多普勒（脐动脉 UA、大脑中动脉 MCA 等）、NT、羊水 MVP/AFI、预产期年龄、双胎等工具，以及脏器目录、孕期知识、宫内治疗主题等内容浏览。

### 1.2 目标用户与使用场景



* 主要用户为具备超声 / 产科背景的专业人员，因此应用内置「**专业版 / 白话版**」两种表达模式（`pro` / `plain`），但唯一入口收敛在「我的」页面。

* 使用场景强调**离线、本机、可复现**：所有计算在本地完成，档案保存在本机，不依赖网络。

### 1.3 产品边界（重要）

项目对「能做什么 / 不能做什么」有非常明确的自我约束：



* **只做确定性计算**：日期、孕周、算术合计、估重等有明确论文 / 公式来源的结果。

* **不做临床推断**：未获批参考模型时，不生成临床分类、疾病概率、分期、评分、输血用量等。INTERGROWTH/CUHK 的百分位、Z-score、均值与 ±2SD 曲线仍在论文参数复核中。

* **账号与知识服务已接通**：游客默认不登录，档案显式微信登录；已发布知识可游客读取。OCR、云同步、订阅提醒、云端分享和反馈接收仍未接通。页面可以展示「真实未接通态」、保存本机草稿，但不会伪造服务成功。

* 工程上明确声明：前端绑定 / 回归测试**不能代替临床验证**，正式发布前仍需真实 AppID、隐私政策、医学审阅及真机验证。

### 1.4 功能与页面规模



* 路由在 `pages.json` 中注册，共 **25 个页面**（对应 README 所称「25 条复用路由」），PRD 的 52 个逻辑页通过这些路由与通用状态组件复用实现。

* 底部三大导航：**工具 / 档案 / 我的**。

* 内容数据规模：37 项脏器目录、22 条知识、17 条宫内治疗主题，支持多档案、双胎 A/B 隔离、收藏、反馈草稿、本机备份与分享图片。

### 2.3 分层架构（核心设计思想）

工程采用清晰的单向分层，页面中**不允许写医学公式**：



```
页面 pages/  ──组合──▶  组件 components/Ga*
     │                     │
     │ 调用                 │ 展示
     ▼                     ▼
 Pinia store（app / profile / workspace）
     │
     ├──▶ engine/（纯函数：校验 + 计算）
     ├──▶ data/（公式来源、工具定义、内容）
     └──▶ utils/storage（本机持久化）
```



* `engine/`**&#x20;纯算法层**：只维护纯 TypeScript，输入确定则输出确定，便于独立测试。

* `components/Ga*.vue`**&#x20;统一组件层**：页面只负责组合组件与管理交互，不重复造 UI。

* `store/`**&#x20;唯一数据入口**：所有持久化写入经 store，保证「先写存储成功，再更新内存」。

* `types/medical.ts`**&#x20;统一医学契约**：计算结果统一用 `CalculationResult<T>` 的 `status: "ready" | "invalid" | "unavailable"` 区分成功与不可用。

### 2.5 状态管理与数据流

三个 Pinia store 均为 **setup store**（函数内用 `ref` 定义状态并 return 暴露）：



1. `store/app.ts`**（全局偏好）**

* 状态：`theme` / `themePreference`（system/light/dark）、`lengthUnit`（cm/mm）、`mode`（pro/plain）、`standard`（INTERGROWTH/CUHK）、`isOffline`。

* 监听系统主题与网络状态；`persist` 先写本地存储再更新内存。

* 存储键：`cy:app:v1`。

1. `store/profile.ts`**（孕期档案，最核心）**

* 管理**多档案**（`profiles`）、当前激活档案（`activeProfileId`）、当前档案的基准 `basis` 与测量记录 `records`。

* 支持单 / 双胎（`fetusCount`、双胎 A/B 标识）、基准修订历史（`basisHistory`）、记录历史快照、同日覆盖确认、多次检查（`keepBoth`）、按 ID 编辑（`replaceId`）。

* 读取时对本地数据做**逐项运行时校验**，兼容旧版单档案结构；损坏时只报错、**阻止覆盖原始数据**。

* 存储键：`cy:profile:v1`（当前写入结构 `version: 2`）。

1. `store/workspace.ts`**（扩展工作区）**

* 管理观察记录 `observations`、产检 / 预约 `appointments`、反馈 `feedback`、收藏 `favorites`、草稿 `drafts`。

* 明确禁止保存出生日期（仅允许临时年龄换算）；反馈仅存本机草稿。

* 存储键：`cy:workspace:v1`。

**统一写盘原则**：写入失败不更新内存，界面不会误显示「已保存」；存储读写经 `utils/storage.ts` 封装 `uni.getStorageSync / setStorageSync`，数据以 JSON 存储。

### 2.6 医学计算引擎（代码实现示例）

`engine/` 包含 `gestation.ts`（孕周 / 日期）、`efw.ts`（估重）、`growth.ts`（生长）、`validation.ts`（校验与单位换算）、`tools.ts`（专科工具算术）、`ocr.ts`（OCR 本地逻辑）。

**示例 1：孕周基准建立（**`engine/gestation.ts`**&#x20;→&#x20;**`createPregnancyBasis`**）**

根据不同方式换算出统一的「等效末次月经日」`lmpEquivalent`，预产期 = 该日 + 280 天：



```
export const GESTATION_DAYS = 280;
// LMP：基准日即末次月经日；EDD：预产期倒推 280 天
// IVF：移植日倒推 (14 + 胚胎龄) 天；D3 胚胎 = 17 天，D5 囊胚 = 19 天
lmpEquivalent = addDays(input.date, -(14 + input.embryoAgeDays));
// CRL：先用 INTERGROWTH 公式由头臀长估算孕周天数，再倒推
```

日期差用 **UTC 日序号**计算（`dateToDay`），避免设备时区 / 夏令时导致小数天或日期偏移。

**示例 2：Hadlock 四参数估重（**`engine/efw.ts`**&#x20;→&#x20;**`calculateHadlockEfw`**）**

先经 `validateBiometry` 校验并用 `toCentimeters` 统一为 cm，再代入 Hadlock 1985 Table II 公式：



```
const log10Grams =
  1.3596 -
  0.00386 * AC * FL +
  0.0064 * HC +
  0.00061 * BPD * AC +
  0.0424 * AC +
  0.174 * FL;
const grams = 10 ** log10Grams; // 公式 ID：HADLOCK_1985_BPD_HC_AC_FL
```

公式系数、`formulaId`、文献 ID 与对照算例绑定维护，不允许随意替换；文献来源统一在 `data/references.ts`。

### 2.7 主题与样式机制



* `styles/theme.ts` 导出 `palettes.light` / `palettes.dark`，是**颜色的唯一来源**，以 CSS 自定义变量（如 `--primary`、`--bg-gradientStart`）形式由 `GaPage` 通过内联 style 注入。

* canvas 绘图与页面读取同一主题，保证图表与界面颜色一致。

* `styles/tokens.scss` 管理非颜色变量（圆角、间距、状态栏高度等）；`glass.scss` 提供玻璃拟态效果；`base.scss` 为基础样式。

* 全局使用自定义导航（`pages.json` 中 `navigationStyle: "custom"`），移动端内容最大宽度 540px 居中。

### 2.8 远程服务边界

`api/http.ts`负责真实请求，`api/wechat.ts`取得微信一次性凭证，`store/account.ts`统一账号和续期；`GaPublishedKnowledge`读取后台当前发布内容。旧的未接通占位模块已删除。

## 三、总结



* **项目角度**：这是一款克制、边界清晰的孕期超声工具，聚焦「本机、离线、确定性计算」，不越界做临床推断，未接通的远程能力如实展示。

* **技术角度**：基于 uni-app + Vue 3 + TypeScript + Pinia 的跨端工程，最大亮点是**严格分层**—— 纯函数 `engine` 负责算法、`Ga*` 组件负责 UI、Pinia store 统一数据与持久化、`types` 统一契约，并辅以单元 / E2E / 设计 / 依赖多重验证，适合对准确性与可审计性要求高的医疗类工具场景。
